# Public deployment (Render)

This project folder contains the complete Privie's Campus Bites app. The included `render.yaml` describes a free Render Node web service. It builds the React client, starts the Express server, and uses `/api/health` for its health check.

## Publish it

1. In Git Bash, open this folder and run `git init -b main`.
2. On GitHub, create an empty **private** repository named `privies-campus-bites` (do not add a README or license there).
3. Back in Git Bash, run:

   ```bash
   git add .
   git status --short
   ```

   Confirm `.env`, `data/`, `node_modules/`, and `dist/` are not listed. Then run:

   ```bash
   git commit -m "Prepare Campus Bites deployment"
   git remote add origin https://github.com/YOUR-USERNAME/privies-campus-bites.git
   git push -u origin main
   ```

   Replace `YOUR-USERNAME` with your GitHub username. The included `.gitignore` keeps secrets, local SQLite data, dependencies, and build output out of Git.
4. In Render, choose **New ? Blueprint**, connect that GitHub repository, and deploy the blueprint. Render will ask for the values marked `sync: false`.
5. Set `DATABASE_URL` to the PostgreSQL connection string from Neon. Use the pooled connection string if available. Keep this value in Render's environment settings; do not put it in GitHub or share it in chat.
6. Set `ADMIN_EMAIL` and a new, strong `ADMIN_PASSWORD` in Render. `JWT_SECRET` is generated by the blueprint. Demo payments are disabled for the public deployment.
7. After the deploy succeeds, copy the `onrender.com` address shown by Render and share it.

The first visit after 15 minutes without traffic can take about a minute while the free service wakes. The app is configured to use Node.js 24.21.0. It must use Neon in production: Render's free service filesystem is temporary, so local SQLite data would be lost when the service restarts or redeploys.

If this Neon database was previously shared or exposed, rotate its password in Neon before putting the new connection string into Render. If the database already contains the admin account, the `ADMIN_EMAIL` / `ADMIN_PASSWORD` values only create an admin when no user with that email exists; they do not reset an existing account's password.
